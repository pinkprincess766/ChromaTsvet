# AGENTS.md — ChromaTsvet

Проект: гибридное приложение для обработки и анализа спектральных/хроматографических данных.

**Основные технологии:**
- Python (PyQt5 + pyqtgraph) — UI, загрузка файлов, экспорт, настройки, идентификация.
- Rust + PyO3 (maturin) — высокопроизводительная сигнальная обработка.

**Архитектурное разделение ответственности (из README):**
- Python владеет пользовательским интерфейсом и оркестрацией.
- Rust владеет численным pipeline (`process_signal`).

---

## 1. Общие принципы работы

- **Понять поток сигнала перед изменениями.** Перед правкой DSP-кода всегда проследи полный путь: загрузка → фильтрация (Python/Rust) → FFT → baseline → нормализация → поиск пиков → идентификация.
- **Правильность > удобство.** Если код может произвести NaN/Inf или неверную частоту — это ошибка, а не "редкий случай".
- **Правило одного владельца.** Числовая обработка сигнала принадлежит Rust. UI и работа с файлами — Python. Не смешивай без явного решения.
- **Рефакторинг main.py — приоритет.** Любая новая функциональность UI/оркестрации должна выноситься в модули, а не добавляться в `python_analyzer/main.py`.
- **Проверяй влияние на частотную ось.** Изменения длины сигнала, window или sample_rate почти всегда влияют на `frequency_axis`.

## 2. Стиль кода и качество

- **Санитизация обязательна.** Все входные сигналы в Rust должны проходить `sanitize_signal`. Не полагайся, что "данные всегда чистые".
- **Нет магических чисел.** Window size, threshold, prominence и т.п. должны иметь именованные константы или хорошо документированные параметры.
- **Комментарии объясняют "почему".** Не пиши то, что видно из кода. Особенно комментируй:
  - порядок операций (baseline перед/после нормализации),
  - почему всегда сохраняется глобальный максимум,
  - как считается частота пика.
- **Явная обработка ошибок.** В Python используй исключения (`FilterError`, `SpectrumFileFormatError`). В Rust — возвращай осмысленные пустые результаты + лог.
- **Именование.** В Rust — snake_case как в остальном коде. В Python — следуй существующим модулям. Избегай `data`, `arr`, `x` без контекста.
- **Тесты для DSP.** Любое изменение в `signal/` требует обновления или добавления теста в `test_rust.py` или Rust unit-тесты.
- **Минимизируй дублирование.** filters.py (Python) и `rust_module/src/signal/filters.rs` — осознанная дублирующаяся зона. Изменения в одном месте должны быть отражены или явно обоснованы.

## 3. Структура проекта и организация файлов

**Запрещено:**
- Добавлять новую логику (методы классов, большие функции) в `python_analyzer/main.py`.
- Класть DSP-логику в Python (кроме тонких обёрток).
- Создавать новые `.py` файлы в корне проекта, если они не тесты или утилиты.

**Куда класть код:**

| Тип кода                        | Место                                      | Примечание |
|--------------------------------|--------------------------------------------|----------|
| Главное окно, диалоги, оркестрация | `python_analyzer/gui/`                    | Создавать новые модули |
| Визуализация (plot helpers)     | `python_analyzer/viz/`                     | Отдельные от MainWindow |
| Бизнес-логика анализа           | `python_analyzer/core/` или новый модуль   | identification, анализ |
| Загрузка/парсинг файлов         | Отдельный модуль в `python_analyzer/`      | Не в main.py |
| Сигнальная обработка            | `rust_module/src/signal/`                  | Только сюда |
| Типы, обмениваемые с Python     | `rust_module/src/types.rs`                 | Держать минимальным |
| Тесты Python                    | Корневые `test_*.py`                       | Держать лёгкими |
| Утилиты для релиза              | `tools/`                                   | — |

- Дублирующиеся `paths.py` (корень и `python_analyzer/`) — технический долг. При рефакторинге стремись к единому источнику.
- `filters.py` в корне — обёртка над SciPy. Не расширяй без решения о владении фильтрацией.

## 4. Работа с Git

- **Conventional Commits** (обязательно):
  - `feat:`, `fix:`, `refactor:`, `perf:`, `test:`, `docs:`, `chore:`
  - Пример: `refactor(python): extract file loader from main.py`
- Не коммить собранные артефакты:
  - `*.pyd`, `*.so`, `rust_module/target/`, `__pycache__/`, `*.log`
- Ветка `main` — только через PR. Для крупных рефакторингов используй feature-ветки.
- Коммит должен быть атомарным. Один PR — одна логическая единица работы.
- Перед большим рефакторингом (`main.py`, ownership фильтров) создай отдельный коммит/ветку с планом изменений.

## 5. Правила взаимодействия нескольких агентов

- **Крупные рефакторинги** (> ~300 строк или затрагивающие структуру) — сначала опиши план в сообщении (что двигаешь, почему, какие файлы затронет).
- При изменении `AGENTS.md` обязательно объясни, зачем правило добавлено/изменено.
- При работе над одной области (например, фильтрация или идентификация) явно укажи, кто сейчас владеет этой областью.
- Если один агент меняет границу между Python и Rust — второй агент должен это заметить и обновить вызовы/тесты.
- Используй `grok inspect` или аналог для проверки загруженных правил перед началом работы.

## 6. Специфические правила проекта

### Сигнальная обработка (критично)
- Порядок в `process_signal` (baseline → area normalization → peak detection) **не менять** без явного обоснования и обновления документации.
- `compute_frequency_axis` должен оставаться точным: `bin_width = sample_rate / signal_len`.
- `detect_peaks_with_settings` всегда должен возвращать хотя бы глобальный максимум (текущая семантика).
- Любое изменение в оценке шума, prominence или min_distance требует теста на синтетических сигналах.

### Фильтрация
- На текущий момент GUI применяет фильтр на Python (`filters.apply_filter`) и передаёт `filter_type="none"` в Rust.
- При изменении стратегии фильтрации обнови:
  1. Python-вызов в `run_analysis()`
  2. Документацию в `lib.rs`
  3. Тесты

### Идентификация веществ
- Текущая реализация (`SpectrumIdentifier`) — заглушка (косинус по интенсивностям).
- Любые улучшения должны двигаться в сторону **пикового** или **feature-based** матчинга.
- Нельзя полагаться только на сырые значения спектра.

### Сборка и запуск
- Изменения в Rust — `cd rust_module && maturin develop`
- Для тестов DSP: `python -m unittest test_rust` (или эквивалент)
- Не полагайся на наличие `spectrometer_rust.pyd` в корне — это собранный артефакт.

### Данные и библиотека
- `library.db` — seed-база. Не храни в ней production-данные без миграции.
- При добавлении веществ через UI они идут в пользовательскую копию БД.
